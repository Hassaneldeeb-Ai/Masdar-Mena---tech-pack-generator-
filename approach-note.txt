Masdr - AI Tech Pack Generator: Approach Note
=============================================

APPROACH
--------
I began by exploring the full project structure to understand the architecture before running it.
The codebase follows a Next.js 15 App Router pattern with a multi-stage AI pipeline at its core.
I identified three key layers: the frontend (React/shadcn/Tailwind), the API layer (Next.js API
routes), and the AI/data layer (multi-provider LLM integration with SQLite persistence). Running
the project was straightforward -- npm install and npm run dev launched the Turbopack dev server
on localhost:3000. The project is well-structured with clear separation between UI components,
business logic (lib/ai/, lib/quality/), and data schemas (lib/schemas/).

AI TOOLS AND MODELS USED
-------------------------
I used the OpenCode CLI (powered by the mimo-v2.5-free model) as the primary AI assistant for
exploring and interacting with the codebase. Specifically:
- OpenCode's explore agent was used to scan the entire project tree, read key files, and return
  a comprehensive summary of architecture, features, and AI integrations -- saving significant
  manual investigation time.
- OpenCode's bash tool was used to install dependencies, start the dev server, and verify
  the application was running.

The project itself integrates multiple AI providers (Google Gemini, OpenAI GPT-4o, Anthropic
Claude Sonnet) for its core pipeline, with automatic key detection and mock fallback. Google
Gemini handles vision analysis, tech pack generation, QA review, image generation (via
gemini-3.1-flash-image), and video generation (via Veo 3.1). The multi-provider architecture
is a smart design choice -- it avoids vendor lock-in and enables offline demo mode.
